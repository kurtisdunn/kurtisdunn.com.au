# SEO Strategy — kurtisdunn.com.au

## Executive Summary

The current site is an SPA (React + Vite) with no server-side rendering — meaning Google sees minimal content. This is the single biggest SEO blocker. The redesign must fix this foundational issue before any on-page optimisation matters.

**Top 3 priorities:**
1. Move to SSR/SSG framework (Astro or Next.js) so pages are crawlable
2. Build keyword-targeted pages for services + industry verticals
3. Establish E-E-A-T signals that competitors (Osher, Automation for Business) already have

## E-E-A-T Strategy for a Solo Australian Operator

### Experience Signals
- Case studies with specific hours saved, dollar figures, and tools used
- "I built this" language — first person, not corporate "we"
- Before/after workflow diagrams in case studies
- Screenshots of real dashboards and automations (anonymised)

### Expertise Signals
- Author bio on every blog post with credentials
- "About" page with career history, certifications, and technical skills
- Detailed methodology descriptions ("Here's how I approach an audit")
- Technical depth in blog posts (not just surface-level)

### Authoritativeness Signals
- Guest posts on Australian business publications (SmartCompany, Kochie's Business Builders, Flying Solo)
- LinkedIn content cross-promoting site content
- Testimonials from named clients with titles and businesses
- ABN displayed in footer
- Google Business Profile fully optimised

### Trustworthiness Signals
- Physical address or "Based in [city], Australia"
- ABN prominently displayed
- Privacy policy and terms
- HTTPS (already in place)
- Transparent pricing guidance (even if not fixed prices)
- "No lock-in" messaging throughout
- Clear contact information (phone, email)
- SSL certificate valid and current

## Technical SEO Requirements

### Critical: Server-Side Rendering

The current SPA architecture (Vite + React Router) renders all content client-side. Google can process JavaScript but:
- It's slower (days to weeks for JS rendering queue)
- It's less reliable (partial rendering, timeout issues)
- Programmatic SEO pages absolutely require SSR/SSG

**Recommendation:** Migrate to **Astro** (preferred for content-heavy sites) or **Next.js**. Use SSG for all static pages, SSR for dynamic/pSEO pages.

### Core Web Vitals Targets

| Metric | Target | Current Risk |
|--------|--------|-------------|
| LCP | < 2.5s | Hero image needs optimisation (WebP, srcset, preload) |
| INP | < 200ms | Low risk (minimal interactivity) |
| CLS | < 0.1 | Font loading (IBM Plex Sans) needs font-display: swap |

### Technical Checklist

- [ ] XML sitemap auto-generated, submitted to GSC
- [ ] Robots.txt allows all crawlers + AI bots
- [ ] Self-referencing canonical on every page
- [ ] Trailing slash policy enforced (no trailing slash)
- [ ] HTTPS with valid SSL
- [ ] 404 page with navigation and CTA
- [ ] Structured data on all pages (see Step 10)
- [ ] Image alt text on all images
- [ ] WebP format for all images
- [ ] Lazy loading for below-fold images
- [ ] Preload hero image and critical fonts
- [ ] Meta viewport tag for mobile
- [ ] hreflang not needed (single-language, single-country)
- [ ] Google Search Console verified
- [ ] Bing Webmaster Tools verified
